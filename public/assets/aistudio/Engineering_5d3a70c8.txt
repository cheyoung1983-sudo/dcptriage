Engineering Specification: Next.js Device Intake Workflow and Shopify GraphQL Data Architecture for D&CP LLC on Vercel
Executive Summary and System Architecture Overview
Modern consumer electronics service operations require an integrated software architecture that unites front-end customer intake, low-level hardware telemetry, statutory compliance, and enterprise resource planning. For Display & Cell Pros LLC (D&CP LLC), a veteran-owned mobile electronics repair laboratory operating in Spokane, Washington (UBI: 605 985 265, UEI: VAJXG5MNYQK8, NAICS: 811210), bridging the physical-to-digital operational divide demands a unified full-stack implementation. The enterprise operates a multi-tier service model spanning high-velocity component replacements to specialized Tier 3 logic board micro-soldering.
To support this operation without incurring the overhead of traditional brick-and-mortar Point of Sale (POS) legacy bloat, the technical architecture utilizes Next.js App Router deployed on Vercel Fluid Compute, integrated with the Shopify Admin GraphQL API. Shopify serves as the core database for inventory, pricing, customer records, and draft order billing. Next.js provides the server-rendered intake interface, executing client-side hardware telemetry, statutory compliance validation under Washington State law, dynamic quote compilation, and transactional synchronization.
The end-to-end data lifecycle begins when a customer or technician accesses the Next.js intake interface hosted on Vercel's edge network. Client-side scripts interface with connected diagnostic hardware via WebUSB or serialized logs to construct a Diagnostic Telemetry File (DTF). This payload is submitted alongside user-entered device information to Next.js Server Actions, where Zod schemas validate the payload against hardware safety limits and legal compliance requirements.
Upon validation, the server action resolves destination-based sales tax for the specific Washington jurisdiction and executes a GraphQL request to Shopify's Admin API. Within Shopify, the system provisions or matches customer records, maps requested repair variations to exact inventory item identifiers, attaches custom diagnostic and statutory metafields, and generates a draft order with an associated checkout URL. When the repair transaction completes, Shopify webhooks notify the Next.js application to adjust real-time stock levels across mobile service locations using targeted inventory mutations.

Shopify Data Table Architecture and GraphQL Schema Design
Shopify’s core database structure isolates product merchandising from physical inventory tracking. Merchandising data resides in the ProductVariant object, while physical inventory tracking, SKUs, and fulfillment attributes reside in the 1:1 linked InventoryItem object. Actual quantities across locations are maintained via InventoryLevel nodes.
To adapt Shopify for electronics repair services without violating platform schema constraints, D&CP LLC utilizes parent Product entries for each device generation (e.g., "iPhone 14 Repair Services"), with ProductVariant nodes representing specific repair combinations. Custom repair attributes—such as device serial numbers, IMEIs, passcodes, diagnostic logs, and statutory disclaimers—are stored in pinned Metafield definitions attached to ProductVariant, DraftOrder, and Customer objects.

Next.js App Router Intake Workflow Implementation
The front-end intake application uses Next.js App Router (app/intake/page.tsx) structured as a multi-step form state machine validated by Zod. The intake funnel executes across four sequential stages:
 * Step 1: Device Reconnaissance: Selection of device manufacturer, generation, model variant, and validation of the 15-digit hardware IMEI.
 * Step 2: Hardware Triage & Telemetry: Failure mode selection, passcode collection, and execution of client-side WebUSB diagnostic polling to generate the DTF stream.
 * Step 3: Statutory Compliance: Presentation of mandatory RCW 19.415 privacy, backup, and parts provenance notices, requiring explicit customer consent checkboxes.
 * Step 4: Quote Engine & Shopify Sync: Dynamic pricing computation, destination tax resolution, and invocation of the server action to construct a Shopify Draft Order and generate a checkout URL.

Next.js Server Action: Shopify Sync Pipeline
The Server Action (app/actions/intake.ts) executes server-side validation, connects to the Shopify Admin GraphQL API, provisions customer records, attaches metafields, creates a draft order, and returns a secure checkout link:
'use server';

import { IntakeFormSchema, IntakeFormData } from '@/lib/validations/intake';
import { revalidateTag } from 'next/cache';

interface ServerActionResponse {
  success: boolean;
  draftOrderId?: string;
  invoiceUrl?: string;
  errors?: Record<string, string[]>;
}

export async function submitDeviceIntake(
  prevState: any,
  formData: FormData
): Promise<ServerActionResponse> {
  // Extract raw form data into object
  const rawData = {
    deviceManufacturer: formData.get('deviceManufacturer'),
    deviceModel: formData.get('deviceModel'),
    imei: formData.get('imei'),
    serviceTier: formData.get('serviceTier'),
    selectedVariantId: formData.get('selectedVariantId'),
    customerReportedIssue: formData.get('customerReportedIssue'),
    devicePasscode: formData.get('devicePasscode') || undefined,
    telemetry: {
      batteryHealthPercentage: Number(formData.get('batteryHealthPercentage')),
      batteryTempCelsius: Number(formData.get('batteryTempCelsius')),
      ammeterDrawAmps: Number(formData.get('ammeterDrawAmps')),
      isShortToGround: formData.get('isShortToGround') === 'true',
    },
    waR2rPrivacyAcknowledged: formData.get('waR2rPrivacyAcknowledged') === 'true',
    waR2rDataBackupAcknowledged: formData.get('waR2rDataBackupAcknowledged') === 'true',
    waR2rPartsProvenanceAcknowledged: formData.get('waR2rPartsProvenanceAcknowledged') === 'true',
    customerEmail: formData.get('customerEmail'),
    customerName: formData.get('customerName'),
    customerPhone: formData.get('customerPhone'),
    destinationZipCode: formData.get('destinationZipCode'),
  };

  // Zod Server-Side Validation
  const validated = IntakeFormSchema.safeParse(rawData);
  if (!validated.success) {
    return {
      success: false,
      errors: validated.error.flatten().fieldErrors as Record<string, string[]>,
    };
  }

  const data: IntakeFormData = validated.data;

  // GraphQL Mutation Payload for Shopify Draft Order
  const draftOrderMutation = `
    mutation draftOrderCreate($input: DraftOrderInput!) {
      draftOrderCreate(input: $input) {
        draftOrder {
          id
          name
          invoiceUrl
          status
        }
        userErrors {
          field
          message
        }
      }
    }
  `;

  const mutationVariables = {
    input: {
      email: data.customerEmail,
      phone: data.customerPhone,
      note: `D&CP Intake | Model: ${data.deviceModel} | Issue: ${data.customerReportedIssue}`,
      shippingAddress: {
        zip: data.destinationZipCode,
        city: 'Spokane',
        province: 'WA',
        country: 'US',
      },
      lineItems: [
        {
          variantId: data.selectedVariantId,
          quantity: 1,
        },
      ],
      metafields: [
        {
          namespace: 'dcp_repair',
          key: 'device_imei',
          value: data.imei,
          type: 'single_line_text_field',
        },
        {
          namespace: 'dcp_repair',
          key: 'diagnostic_tier',
          value: data.serviceTier,
          type: 'single_line_text_field',
        },
        {
          namespace: 'dcp_repair',
          key: 'device_passcode',
          value: data.devicePasscode || 'NONE_PROVIDED',
          type: 'single_line_text_field',
        },
        {
          namespace: 'dcp_repair',
          key: 'dtf_payload',
          value: JSON.stringify(data.telemetry),
          type: 'json',
        },
        {
          namespace: 'dcp_repair',
          key: 'wa_r2r_accepted',
          value: 'true',
          type: 'boolean',
        },
      ],
    },
  };

  try {
    const response = await fetch(
      `https://${process.env.SHOPIFY_STORE_DOMAIN}/admin/api/2026-01/graphql.json`,
      {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          'X-Shopify-Access-Token': process.env.SHOPIFY_ADMIN_API_TOKEN!,
        },
        body: JSON.stringify({
          query: draftOrderMutation,
          variables: mutationVariables,
        }),
        next: { tags: ['shopify-orders'] },
      }
    );

    const result = await response.json();

    if (result.errors || result.data?.draftOrderCreate?.userErrors?.length > 0) {
      const gqlErrors = result.data?.draftOrderCreate?.userErrors || result.errors;
      return {
        success: false,
        errors: { server: [gqlErrors[0].message] },
      };
    }

    const draftOrder = result.data.draftOrderCreate.draftOrder;

    // Purge cached inventory counts across site
    revalidateTag('shopify-inventory');

    return {
      success: true,
      draftOrderId: draftOrder.id,
      invoiceUrl: draftOrder.invoiceUrl,
    };
  } catch (error) {
    return {
      success: false,
      errors: { server: ['Fatal connection failure to Shopify Admin endpoint'] },
    };
  }
}

2. Edge Middleware for Destination-Based Tax Resolution
Washington State enforces destination-based retail sales tax. The intake middleware (middleware.ts) inspects the customer’s destination ZIP code at the Edge to resolve local jurisdiction location codes (e.g., Spokane City code 3202 at 9.1% vs. Spokane Valley code 3213 at 9.0%) prior to quote compilation:
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  const response = NextResponse.next();
  const zip = request.nextUrl.searchParams.get('zip') || '99201';

  // Washington State Destination Tax Jurisdiction Resolver
  let taxRate = 0.091; // Default Spokane City Combined Rate (9.1%)
  let locationCode = '3202'; // Spokane City

  if (['99206', '99212', '99216'].includes(zip)) {
    taxRate = 0.090; // Spokane Valley Rate (9.0%)
    locationCode = '3213'; // Spokane Valley Jurisdiction
  }

  response.headers.set('x-dcp-tax-rate', taxRate.toString());
  response.headers.set('x-dcp-location-code', locationCode);

  return response;
}

import { NextResponse } from 'next/server';
import crypto from 'crypto';

export async function POST(request: Request) {
  const rawBody = await request.text();
  const hmacHeader = request.headers.get('X-Shopify-Hmac-SHA256');
  const secret = process.env.SHOPIFY_WEBHOOK_SECRET!;

  const calculatedHmac = crypto
    .createHmac('sha256', secret)
    .update(rawBody, 'utf8')
    .digest('base64');
